# Архитектурные границы

Текущее состояние — [overview.md](overview.md).

## Слои
| Слой | Каталог | Правила |
|---|---|---|
| Domain / pure logic | `src/**` | Чистые функции, без I/O, без глобального состояния, без чтения `process.env`. |
| Tests | `test/**` | Только `node:test` + `node:assert/strict`. Импорт продукта по относительному пути (`../src/...`). |
| Управляющая документация | `docs/**`, `*.md` в корне | Меняет только Claude. Воркеры не трогают. |

## Правила зависимостей
- `src/**` не импортирует ничего из `test/**`.
- `src/**` не добавляет внешние npm-пакеты (см. [AGENTS.md](../../AGENTS.md#6-зависимости)).
- Побочные эффекты (файлы, сеть, время, процесс) живут в отдельном адаптерном модуле, а не внутри чистой логики.
  Такого модуля сейчас нет; он появляется только когда задача действительно этого требует.

## Публичный API
- Публичным считается всё, что экспортируется из `src/**`. Сейчас это `parseDuration`.
- Сигнатуры, классы бросаемых ошибок и семантика возвращаемого значения — часть контракта.
- Ломающее изменение допускается только при явном указании в ТЗ и с обновлением тестов и ADR.

## Ошибки
- Невалидный тип аргумента → `TypeError`.
- Валидный тип, но недопустимое значение → `RangeError`.
- Собственные классы ошибок не вводятся без ADR. Ошибки не проглатываются и не логируются внутри чистой логики.

## Именование и структура
- Один модуль — одна ответственность, файл `src/<domain>.js`, тест-близнец `test/<domain>.test.js`.
- Файлы в нижнем регистре, ESM-импорты с явным расширением `.js`.

## ADR
Значимое архитектурное решение (новый слой, зависимость, ломающее изменение API, смена рантайма)
фиксируется как ADR в `docs/architecture/adr/NNNN-<slug>.md` со структурой:
**Context → Decision → Consequences → Status** (Proposed / Accepted / Superseded).
Каталог `adr/` создаётся при первом ADR; сейчас ADR нет.
