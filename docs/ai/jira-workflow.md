## Статусы и переходы
| Статус (RU / EN) | status ID | transition ID |
|---|---|---|
| To Do / К выполнению | `10004` | `11` |
| In Progress / В работе | `10005` | `21` |
| In Review / В процессе проверки | `10006` | `31` |
| Brief / Breaf | `10007` | `41` |
| Done / Готово | `10008` | `51` |

**Стабильный идентификатор — status ID.** Имена статусов локализованы и различаются написанием
(`Brief` / `Breaf`), сопоставлять по строке запрещено.

## Метки
| Метка | Смысл |
|---|---|
| `ai-ready` | Входной триггер: задачу можно брать в работу |
| `ai-needs-input` | Нужны ответы пользователя, автоматическая работа приостановлена |
| `ai-changes-requested` | Возврат Qwen на исправление после `CHANGES_REQUIRED` |
| `ai-awaiting-merge` | Claude принял PR, ожидается действие человека |
| `ai-blocked` | Автоматическое продолжение невозможно (вместе с Flagged = `Impediment`) |
| `mode-mvp` / `mode-product` | Режим разработки, см. [brief-template.md](brief-template.md) |

## Правила
1. Один coordinator-run обрабатывает **максимум одну** Jira-задачу.
2. **Claim:** снять `ai-ready` и перевести задачу в Brief (`10007`, transition `41`) — атомарно, одним шагом,
   до любой другой работы. Снятая метка `ai-ready` — признак того, что задача занята.
3. Нехватка данных → `ai-needs-input`, задача остаётся в Brief, run завершается.
   Метку `ai-ready` возвращает **пользователь** после ответов; сам себе Claude её не возвращает.
4. Реализация → In Progress (`10005`/`21`), ревью → In Review (`10006`/`31`).
5. `CHANGES_REQUIRED` → метка `ai-changes-requested`, задача остаётся в In Progress.
6. `ACCEPT` + созданный PR → метка `ai-awaiting-merge`, задача в In Review.
7. **Done (`10008`/`51`) ставится только после подтверждённого merge**, проверенного фактически, а не по намерению.
8. Невозможность продолжить → `ai-blocked` + Flagged = `Impediment` + комментарий с причиной.

## Комментарии
В комментариях задачи хранятся: **Run ID, Task ID, Dispatch IDs, ветки, коммиты (sha), результаты тестов,
verdict, PR URL**. Комментарий — журнал run'а; без него run считается незавершённым.

## Ограничения на мутации
- **Не создавать Jira Subtask** на каждую техническую попытку Qwen. Попытки живут в комментариях.
- **Не выполнять ни одной мутации** (transition, label, comment, edit) без предварительного
  перечитывания задачи и сверки `key`. Ключ из памяти или из вывода поиска перепроверяется чтением задачи.
- Не редактировать чужие комментарии и поля, не относящиеся к AI-контуру.
