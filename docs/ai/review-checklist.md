# Чек-лист ревью (выполняет Claude)

Ревью выполняется **независимо**: Claude сам читает diff и сам запускает команды, не доверяя отчёту воркера.

## Проверки
| # | Что | Как |
|---|---|---|
| 1 | Соответствие acceptance criteria | Каждый пункт ТЗ отображён в код и в тест; ни одного невыполненного |
| 2 | Scope diff | `git show --stat <sha>` — изменены только «ожидаемые файлы», лишних файлов нет |
| 3 | Архитектурные границы | Соответствие [../architecture/boundaries.md](../architecture/boundaries.md): слои, чистота `src/**`, публичный API |
| 4 | Обработка ошибок | `TypeError` / `RangeError` по контракту; ошибки не проглочены, нет `console.log` |
| 5 | Тесты | Новые тесты реально падают на старом коде; покрыты краевые случаи и ошибки |
| 6 | Безопасность | Нет секретов, нет абсолютных путей пользователя, входные данные валидируются |
| 7 | Обратная совместимость | Публичный API не сломан, если ломающее изменение не разрешено в ТЗ |
| 8 | Зависимости | `package.json` не изменён, `node_modules` и lock-файлы не появились |
| 9 | `git status --short` | Дерево чистое, никаких неотслеживаемых остатков |
| 10 | Commit | Ровно один commit, сообщение из ТЗ, без мусорных merge-коммитов |

Плюс гейты из [../architecture/quality-gates.md](../architecture/quality-gates.md), запущенные Claude заново.

## Вердикт
Ровно одно значение, без промежуточных формулировок:

- **ACCEPT** — все пункты выше пройдены.
- **CHANGES_REQUIRED** — любой пункт не пройден. К вердикту прикладывается нумерованный список
  конкретных правок (файл + что именно), без общих рассуждений.

## Итерации
- Максимум **две** итерации исправлений на одну задачу.
- Если после второй итерации вердикт снова `CHANGES_REQUIRED` — задача помечается `ai-blocked`
  + Flagged=Impediment и эскалируется человеку (см. [jira-workflow.md](jira-workflow.md)).
- Каждая итерация фиксируется комментарием в Jira: номер итерации, вердикт, список правок.
