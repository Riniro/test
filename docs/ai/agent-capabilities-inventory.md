# Инвентаризация возможностей агентов по ролям (KAN-21)

Подготовительный шаг к KAN-15. Здесь **ничего не включается и не настраивается**: зафиксировано то, что
доступно агентам на момент замера. Состояние на 2026-11-25, Qwen Code 0.28.0.

## Как читать отчёт

Каждое утверждение помечено способом получения:

| Метка | Значение |
|---|---|
| **ВЫЗОВ** | результат фактического вызова инструмента или команды, вывод приведён |
| **ЧТЕНИЕ** | прочитан файл или список, который агент видит у себя; сам инструмент не вызывался |
| **НЕПРОВЕРЕНО** | по документации или по выводу; фактическим вызовом не подтверждено |

Раздел 1 собран воркером `qwen-code` (задание `investigation`, репозиторий не менялся). Для пунктов с меткой
ВЫЗОВ в разделе 1 различается источник. Повторяли не одно и то же, поэтому источники разделены точно:

- **«повторено координатором и ревьюером»** — версия Qwen, `qwen mcp list`, `.qwen/settings.json`,
  `ls ~/.qwen/skills`, отсутствие ключа `mcpServers` в `~/.qwen/settings.json`;
- **«повторено координатором»** — провайдер модели, размер контекстного окна и тип значения ключа
  (по длине и равенству плейсхолдеру; значение не выводилось). Ревьюер этих пунктов не повторял;
- **«со слов воркера»** — вызов выполнил только воркер, и никто его не повторял
(`web_fetch`, `run_shell_command`, `read_file`, `write_file`, `tool_search`, отказ `web_search`). Раздел 2 — окружение Claude-координатора; сверка
со своим окружением — задача независимого Claude-ревьюера (критерий 6 KAN-21).

Секреты и адреса внутренних серверов в отчёт не входят. Пути даны относительно `~` и корня репозитория.

## 3. Чего не хватает для поиска

**Может ли Qwen сегодня сам найти и прочитать официальную документацию? По состоянию наблюдения (Qwen Code 0.28.0,
конфигурация этого репозитория и пользователя) — нет.** Вывод опирается на единственный отказ моста (1.5) плюс
отсутствие находок в `tool_search`; повторяемость не проверялась.

Цепочка обрывается на **первом шаге — поиске**:

1. Поиск: инструмента нет. Прямой вызов `web_search` отклонён мостом: `Deferred tool "web_search" is not registered
   in this session` (1.5). MCP-серверов, которые могли бы дать поиск, ноль (1.4).
2. Чтение: работает (`web_fetch`, 1.6), но **только по заранее известному URL**.

То есть Qwen способен прочитать страницу, если URL ему передан (например, в ТЗ координатором), и не способен
найти нужную страницу сам. Claude закрывает этот шаг собственным `WebSearch` и субагентом `web-fetch`.

Справка, НЕПРОВЕРЕНО вызовом: по результатам обычного веб-поиска (страница Web Search в документации Qwen Code,
`https://qwenlm.github.io/qwen-code-docs/en/developers/tools/web-search/`, прочитаны сниппеты, не страница) встроенный
`web_search` в новых версиях Qwen Code убран, а поиск подключается через MCP-сервер в `mcpServers`. Это согласуется
с наблюдением 1.5, но само по себе его не подтверждает. **Источники расходятся:** по замечанию ревьюера, страницы той же
документации на других языках (например корейская) описывают opt-in встроенный `web_search` с провайдером DashScope;
какая из версий документации соответствует установленной 0.28.0, не установлено.

## 5. Ограничения замера

- Раздел 1 — наблюдения одного воркера в одной сессии; повторяемость между сессиями и обновлениями Qwen не проверялась.
- Работоспособность всех инструментов и навыков, кроме отмеченных ВЫЗОВ, не проверена.
- Состояние авторизации не-Atlassian MCP-серверов Claude выведено по набору их инструментов, а не по вызову.
- Отчёт воркера лежал вне репозитория; здесь он пересобран координатором, ошибки первой версии (число навыков 16/15,
  «user»-навык, «12 проверено», внутренний адрес) исправлены по дополнению и по независимой перепроверке.
